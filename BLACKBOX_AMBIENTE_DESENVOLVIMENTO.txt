AMBIENTE DE DESENVOLVIMENTO BLACK-BOX - SOBERANIA DO CODIGO
==========================================================

Objetivo: Nenhuma telemetria ou codigo da Cara Core Informatica deve sair do equipamento sem permissao expressa. VS Code/Cursor restrito a telemetria desligada e, opcionalmente, apenas localhost (Ollama).


1. CONFIGURACOES NO SETTINGS.JSON (TELEMETRIA E CRASH REPORTER)
----------------------------------------------------------------

Arquivo (Cursor): %APPDATA%\Cursor\User\settings.json
Arquivo (VS Code): %APPDATA%\Code\User\settings.json

Adicione ou ajuste as chaves abaixo:

  Chave                              Valor      Efeito
  telemetry.telemetryLevel           "off"      Desativa toda telemetria do nucleo (uso, erros, eventos).
  telemetry.enableCrashReporter      false     Desativa envio de relatorios de crash.
  enable-crash-reporter              false     Flag do Electron/crash reporter (redundante com o anterior).
  update.mode                        "none"    Opcional: nao busca atualizacoes automaticamente.
  extensions.autoCheckUpdates       false     Opcional: nao verifica atualizacoes de extensoes.
  extensions.autoUpdate              false     Opcional: nao atualiza extensoes automaticamente.

Cursor (especifico):

  - Privacy Mode: em Cursor Settings, General, Privacy Mode, ative Privacy Mode.
    Isso reduz retencao de dados com provedores de modelo (prompts/codigo nao usados para treino).
    Se existir chave em settings.json, use: "cursor.privacyMode": true (conforme documentacao atual do Cursor).

Resumo minimo no JSON:

  {
    "telemetry.telemetryLevel": "off",
    "telemetry.enableCrashReporter": false,
    "enable-crash-reporter": false
  }

Reinicie o editor apos alterar. Mesmo com isso, o editor pode ainda fazer DNS lookups para dominios Microsoft; para bloquear de fato, use o arquivo hosts (secao 3).


2. EXTENSOES QUE COSTUMAM ENVIAR DADOS (E COMO LIMITAR)
-------------------------------------------------------

Estas extensoes costumam ter telemetria ou envio de codigo/uso para nuvem. Limite-as conforme necessidade.

  Extensao / familia                    O que costumam fazer              Como limitar
  GitHub Copilot                        Envia trechos de codigo e         Desative na extensao ou nao use em
                                        contexto para nuvem.                repositorios sensiveis. Cursor: use
                                                                           apenas modelos locais (Ollama) e
                                                                           Privacy Mode.
  GitLens                               Uso e, em versoes, telemetria.     "gitlens.telemetry.enabled": false
  Red Hat (Java, YAML, etc.)            Telemetria de uso.                "redhat.telemetry.enabled": false
  Docker                                Telemetria e analytics.            Desative em Docker extension settings
  Azure / MS SQL                        Telemetria e diagnostico.          Desative telemetria nas configs de
                                                                           cada extensao.
  Codeium / Tabnine / similares         Enviam contexto de codigo para     Desative ou nao instale em ambiente
                                        servidores.                         black-box.
  Qualquer extensao "AI" que use nuvem  Envio de codigo/prompts.           Use apenas modelos locais (Ollama).

Boas praticas:

  - Em Extensions, revise cada extensao: abra Details e procure por Telemetry, Data, Privacy.
  - Desative telemetria por extensao quando houver opcao em Settings ou em settings.json (chaves com nome da extensao).
  - Para maxima soberania: use o minimo de extensoes e prefira as que nao dependem de servidores externos para o seu codigo.


3. SCRIPT PARA BLOQUEAR DOMINIOS DE TELEMETRIA NO HOSTS (WINDOWS)
------------------------------------------------------------------

O script adiciona entradas ao arquivo hosts do Windows para resolver dominios conhecidos de telemetria da Microsoft e do ecossistema VS Code para 0.0.0.0, impedindo que o trafego saia.

Arquivo: block-telemetry-hosts.py ou mascote_blackbox.py (Python 3)

Uso: Executar como Administrador (terminal ou Prompt de Comando elevado):

  python block-telemetry-hosts.py

Para testar sem alterar o hosts (nao exige admin): python block-telemetry-hosts.py --dry-run

Depois de executar: ipconfig /flushdns


4. FIREWALL DO WINDOWS: OLLAMA (LOCALHOST:11434) E RESTRICAO A TELEMETRIA
--------------------------------------------------------------------------

Objetivo: Garantir que o Cursor/VS Code possa falar com o Ollama em localhost:11434 e, na medida do possivel, nao alcancar servidores de telemetria (sem quebrar Git, npm, etc.).

4.1 Permitir apenas localhost:11434 (Ollama)

  O trafego para 127.0.0.1:11434 ja e local; o Firewall do Windows normalmente nao bloqueia conexoes de loopback. Se voce tiver regras restritivas:

  - Permitir entrada em 11434: apenas se o Ollama estiver vinculado a 0.0.0.0 e voce quiser regra explicita.
  - Permitir saida para 127.0.0.1: normalmente ja permitida por padrao.

  Nao e necessario criar regra especial so para "VS Code -> localhost:11434" a menos que voce tenha bloqueado tudo e esteja liberando excecoes.

4.2 Bloquear saida para servidores de telemetria (porta 443)

  A abordagem mais pratica e nao bloquear toda a porta 443 para o editor (senao quebra atualizacoes, extensoes, Git, etc.), e sim:

  1. Bloquear por nome de host: usar o arquivo hosts (script da secao 3) para que os dominios de telemetria resolvam para 0.0.0.0. Assim, mesmo que o processo tente conexao HTTPS (443), o destino sera invalido.

  2. Opcional, regras de Firewall por processo: Se quiser bloquear por destino (IP), seria necessario manter uma lista de IPs de telemetria (que mudam) e criar regras Block outbound para o executavel do Cursor/VS Code. Isso e avancado e de manutencao custosa; o bloqueio via hosts e mais simples e eficaz.

  Exemplo conceitual (apenas se voce tiver lista de IPs):

  - Abrir Windows Defender Firewall with Advanced Security.
  - Outbound Rules, New Rule, Custom, Program: %LOCALAPPDATA%\Programs\cursor\Cursor.exe (ou o caminho do Code.exe).
  - Scope: Remote IP addresses = lista dos IPs de telemetria (nao recomendado como unica medida).
  - Action: Block.

  Recomendacao: usar hosts e telemetria desligada no settings; usar firewall apenas se precisar de politica extra (ex.: rede corporativa).

4.3 Resumo firewall

  Acao                                    Como
  Ollama (localhost:11434)                 Ja permitido em loopback; sem regra extra na maioria dos casos.
  Telemetria (443)                        Bloquear dominios via hosts (script). Opcional: regras de bloqueio por IP.
  Nao bloquear 443 globalmente para o     Evita quebrar atualizacoes, extensoes e Git.
  editor


5. CHECKLIST RAPIDO
-------------------

  - telemetry.telemetryLevel "off" e telemetry.enableCrashReporter false em settings.json.
  - Cursor: Privacy Mode ativado em Settings, General.
  - Extensoes: telemetria desligada (Red Hat, GitLens, Docker, etc.); evitar extensoes "AI" em nuvem em projeto Cara Core.
  - Script block-telemetry-hosts.py ou mascote_blackbox.py executado como Administrador; ipconfig /flushdns apos.
  - Ollama em localhost:11434 para uso de modelos locais sem vazamento.
  - Opcional: update.mode "none" e desativar auto-update de extensoes se quiser minimo trafego.

Soberania do Codigo - Cara Core Informatica. Nada sai do equipamento sem sua permissao expressa.
